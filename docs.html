vib-MC/Documentation

From the vib-MC Wiki, the documentation for a server nobody wrote by hand.

This page covers running the server and writing plugins. For what the server does and does not support, see vib-MC.

A vib-MC server is one jar in one folder. A vib-MC plugin is one jar in the plugins/ folder next to it, carrying a plugin.yml and one class that extends VibMCPlugin. That is the entire contract.

[edit] Requirements

You need Why Where
Java 8 or newer Both the server and plugins compile and run against Java 8+. If in doubt, install the latest LTS: it still runs Java 8 bytecode. adoptium.net
The vib-MC jar The whole server. There are no extra files to hunt down. Latest release
A Minecraft client Anything from 1.8 to 26.1.2, except 1.16, 1.16.1 and 1.19.3. No mods, no Forge, no Fabric: a vanilla launcher profile is enough. Any launcher that can pin a version
A JDK plugins only Running the server needs only a JRE. Compiling a plugin needs a full JDK and the vib-MC jar on the classpath. Gradle is optional, javac is fine. javac and jar from any JDK 8+

[edit] Running the server

Put the jar in an empty folder and start it. There is nothing to configure first.

Terminal 
# put vib-mc.jar in an empty folder first
$ java -jar vib-mc.jar

What the first start does

The server binds to 0.0.0.0:25565, writes a server.properties, and creates a plugins/ folder. Join with any supported client on localhost.

Configuration

server.properties holds the port, world name, seed, view distance and the online-mode switch. Edit it before starting, or while the server is stopped: values are read at boot only.

Key Default
port25565
seedblank, meaning random per new world
online-modetrue

Server console

The console accepts the same commands players do. Select one to copy it.

[edit] Writing a plugin

The plugin.yml file

It lives at the root of the jar and is read as a Java properties file, so plain key=value lines. Only name, version and main are required.

plugin.yml
name=MyPlugin
version=1.0.0
main=com.example.MyPlugin
description=Does a thing, sometimes
authors=you

The main class

Extend VibMCPlugin and override onEnable() to register commands and listeners. Compile against the vib-MC jar:

Terminal
$ javac -cp vib-mc.jar -d out src/com/example/MyPlugin.java
$ jar cf MyPlugin.jar -C out . plugin.yml

Worked example: /gmc

The full source of a real plugin that puts you in creative mode when you type /gmc. Copy it, compile it, drop the jar in plugins/, restart the server.

src/com/example/MyPlugin.java
package com.example;

import net.vibmc.command.Command;
import net.vibmc.command.CommandSender;
import net.vibmc.entity.ServerPlayer;
import net.vibmc.player.GameMode;
import net.vibmc.plugin.VibMCPlugin;

public class MyPlugin extends VibMCPlugin {
    @Override
    public void onEnable() {
        getCommandManager().register(new Command("gmc",
                "Switch to creative mode", "/gmc", null) {
            @Override
            public boolean execute(CommandSender sender, String[] args) {
                if (!sender.isPlayer()) {
                    sender.sendMessage("{\"text\":\"§cOnly players can use /gmc\"}");
                    return false;
                }
                ServerPlayer player = sender.getPlayer();
                player.setGameMode(GameMode.CREATIVE);
                player.sendMessage("{\"text\":\"§aYou are now in creative mode.\"}");
                return true;
            }
        });
    }
}

Listening to events

Implement Listener, annotate methods with @EventHandler, then register the listener in onEnable().

JoinListener.java
import net.vibmc.plugin.Listener;
import net.vibmc.plugin.EventHandler;
import net.vibmc.plugin.event.PlayerJoinEvent;

public class JoinListener implements Listener {
    @EventHandler
    public void onJoin(PlayerJoinEvent event) {
        event.getPlayer().sendMessage(
                "{\"text\":\"§aWelcome to the vibe.\"}");
    }
}
Inside onEnable()
getPluginManager().registerEvents(new JoinListener(), this);

    [edit] API reference

    Entry points

    To do this Call
    Register a command getCommandManager().register(command)
    Register listeners getPluginManager().registerEvents(listener, this)
    Log lines getLogger().info("...")
    Reach players VibMC.getInstance().getPlayerManager()
    Reach worlds and blocks VibMC.getInstance().getWorldManager()
    Check permissions getPluginManager().getPermissionManager()
    Send messages or packets player.sendMessage(json), player.getUser().sendPacket(packet)

    Events

    Event Fires when
    PlayerJoinEventA player finishes logging in.
    PlayerQuitEventA player disconnects.
    ChatEventA player chats. Cancellable.
    TickEvent.Start / TickEvent.EndEvery server tick, before and after.

    [edit] Notes and gotchas

    Building a plugin by hand needs vib-mc.jar in the working directory or on the classpath. Without it the compile fails. Grab it from the releases page first.

    • Messages are raw JSON chat components, for example {"text":"hello"}. Section-sign colour codes work.
    • Command takes a permission string. null means anyone can run it.
    • Plugins load at startup in no particular order. depends is parsed but not enforced yet.
    • Compile against --release 8 if your JDK is picky. The server runs Java 8 bytecode.
    • Restart the server to load or unload a plugin.
