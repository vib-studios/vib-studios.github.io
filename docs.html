Run it. Break it. Plugin it.

Everything you need to get a vib-MC server up and to write your own plugins. Written by an AI, for whoever wants to continue the vibe.

Requirements

What you need before anything else. Keep it simple.

Java 8 or newer

Both the server and plugins compile and run against Java 8+. If in doubt, install the latest LTS (e.g. Temurin 21 or 17) — it still runs Java 8 bytecode.

download: adoptium.net (Temurin)

The vib-MC jar

Grab the latest release jar from the downloads section on the main page. That's the whole server — no extra files to hunt down.

latest release: v0.0.7

A Minecraft client

Since v0.0.6 the server speaks many protocol versions — anything from 1.8 to 26.1.2, except 1.16, 1.16.1 and 1.19.3. A vanilla launcher profile works — or any launcher that can pin that version.

no mods needed, no forge, no fabric

Only for plugins: a JDK

Running the server needs a JRE. Compiling plugins needs a full JDK and the vib-MC jar on the classpath. Gradle is optional — javac works fine.

javac / jar from any JDK 8+

Run the server

Three commands, zero configuration. First run generates everything it needs.

quickstart
# 1. put vib-mc.jar in an empty folder
$ java -jar vib-mc.jar

What happens

The server binds to 0.0.0.0:25565, generates a server.properties, and opens a plugins/ folder. Join with any supported client on localhost.

Config

server.properties holds the port, world name, seed, view distance, and the online-mode switch. Edit it before or while the server is stopped.

port: 25565 · seed: blank (random per new world) · online-mode: true

Server console

The console accepts the same commands as players: /help, /tp, /gamemode, /time, /weather, /give, /kill, /say, /seed, /save-all, /save-on, /save-off, /stop, /list, /op, /deop, /kick, /dimension.

Write a plugin

A plugin is a jar dropped into plugins/. It ships a plugin.yml and one class that extends VibMCPlugin. That's the whole contract.

1. plugin.yml

Lives at the root of the jar. It is read as a Java properties file — plain key=value lines. Only name, version and main are required. 

name=MyPlugin
version=1.0.0
main=com.example.MyPlugin
description=Does a thing, sometimes
authors=you

2. The main class

Extend VibMCPlugin. Override onEnable() to register commands and listeners. Compile against the vib-MC jar: 

javac -cp vib-mc.jar -d out src/com/example/MyPlugin.java
jar cf MyPlugin.jar -C out . plugin.yml

3. A working example: /gmc

This is the full source of a real plugin that puts you in creative mode when you type /gmc. Copy it, compile it, drop it in plugins/, restart, done. 

package com.example;

import net.vibmc.command.Command;
import net.vibmc.command.CommandSender;
import net.vibmc.entity.ServerPlayer;
import net.vibmc.player.GameMode;
import net.vibmc.plugin.VibMCPlugin;

public class MyPlugin extends VibMCPlugin {
    @Override
    public void onEnable() {
        getCommandManager().register(new Command("gmc",
                "Switch to creative mode", "/gmc", null) {
            @Override
            public boolean execute(CommandSender sender, String[] args) {
                if (!sender.isPlayer()) {
                    sender.sendMessage("{\"text\":\"§cOnly players can use /gmc\"}");
                    return false;
                }
                ServerPlayer player = sender.getPlayer();
                player.setGameMode(GameMode.CREATIVE);
                player.sendMessage("{\"text\":\"§aYou are now in creative mode.\"}");
                return true;
            }
        });
    }
}

4. Listening to events

Implement Listener, annotate methods with @EventHandler, then register them in onEnable(): 

import net.vibmc.plugin.Listener;
import net.vibmc.plugin.EventHandler;
import net.vibmc.plugin.event.PlayerJoinEvent;

public class JoinListener implements Listener {
    @EventHandler
    public void onJoin(PlayerJoinEvent event) {
        event.getPlayer().sendMessage(
            "{\"text\":\"§aWelcome to the vibe.\"}");
    }
}
getPluginManager().registerEvents(new JoinListener(), this);

    API reference

    The useful surface, in one table. Everything lives in net.vibmc.* — the jar is your javadoc.

    you get from
    register commands getCommandManager().register(new Command(...))
    register listeners getPluginManager().registerEvents(listener, this)
    log lines getLogger().info("...")
    players VibMC.getInstance().getPlayerManager()
    worlds & blocks VibMC.getInstance().getWorldManager()
    permissions getPluginManager().getPermissionManager()
    send messages / packets player.sendMessage(json), player.getUser().sendPacket(packet)
    event when
    PlayerJoinEvent a player finishes logging in
    PlayerQuitEvent a player disconnects
    ChatEvent a player chats (cancellable)
    TickEvent.Start / TickEvent.End every server tick, before/after

    Notes & gotchas

    • Messages are raw JSON chat components — {"text":"hello"}. § codes work.
    • Command takes a permission string; null means anyone.
    • Plugins load at startup, in no particular order. depends is parsed but not enforced yet.
    • Compile against --release 8 if your JDK is picky — the server runs Java 8 bytecode.
    • ⚠ Building a plugin by hand? You need vib-mc.jar in the directory (or on the classpath) or the compile fails — grab it from the releases page first.
    • Restart the server to load or unload plugins.
